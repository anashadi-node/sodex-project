Mengapa “profit, bukan volume”

Prinsip lama volume is a result of profitability masih berlaku, tetapi arahnya dibalik dari masa farming: dulu volume adalah target dan profit mengikuti; sekarang profit adalah target dan volume hanyalah konsekuensi eksekusi. SOLEX.md menyatakan secara eksplisit revisi 2026-08-01: “Goal = profit maximal swing trading 1h–48h”, sedangkan CLAUDE.md dan kanon 31-Okt mengunci window 1–30 jam.

Kenapa 1–30 jam?Window swing cukup panjang untuk mengurangi noise mikrostruktur, cukup pendek untuk siklus belajar harian. Butuh catatan: HUKUM_BUKTI menunjukkan panjang window tidak mempercepat pembuktian statistik; W hilang dari rumus t. Jadi timeframe dipilih untuk operasi, bukan untuk “membuktikan lebih cepat”.

02Filosofi & First Principles

Delapan prinsip yang mengikat semua keputusan—termasuk keputusan untuk tidak melakukan apa pun.

  1. Falsification-first. Hipotesis, window, biaya, dan gate dibekukan sebelum hasil terlihat. Klaim ilmiah hanya sah jika bisa dibuktikan salah dan belum terbantahkan.
  2. Net alpha, bukan gross PnL. alpha_net = r_trade − β_side × r_BTC − fee − slippage − funding, dengan β = +1 long, −1 short. Data kurang → UNSETTLED, bukan dikarang.
  3. Evidence-first architecture. Setiap lane punya peran ilmiah; naik-turun status lane berdasarkan statistik, bukan perasaan atau satu hari hijau.
  4. Backtest menghasilkan kandidat; forward/OOS yang memutuskan. Tidak ada lookahead, tidak ada shuffle:true pada time-series, tidak ada penyelamatan post-hoc.
  5. n kecil = data invalid/monitor, bukan verdict. Multiple testing wajib dikoreksi (BH-FDR / Bonferroni). Satu trade tidak bisa disebut “terbukti”.
  6. Safety & privacy pertama. dry_run=true default, fail-closed, kill switch, batas modal/order, IOC limit, tanpa retry order ambigu, kredensial tidak pernah masuk git/log.
  7. Deep loop learning otonom. Sistem berjalan 24/7, tetapi refleksi harus deterministik dan tidak boleh menaruh LLM di jalur keputusan (PRAREG-40).
  8. Target fundamental hanya berubah lewat amandemen tertulis + persetujuan Owner. Agen tidak boleh melunakkan gate demi hasil hijau.

04Hukum Bukti & Statistik

Bagian ini menjelaskan mengapa “hijau” tidak otomatis berarti “benar”.

Aritmetika kekuatan bukti

t = (r / s) × √T

r = edge per jam, s = volatilitas per jam, T = jam kalender.
Panjang window W hilang dari persamaan.
Leverage L juga hilang: μ dan σ sama-sama ×L, rasio μ/σ tidak berubah.
Waktu sampai |t| ≥ 4,11 (Bonferroni α=0,05)
Sharpe tahunanTahunCatatan

0,6%/48 jam (sd 11,03%)31,34,5× lebih sulit dibuktikan.

Prediksi yang sudah terbukti aman dipegang: sebelum 25-Nov, mustahil membuktikan 0,8% dengan ambang |t| ≥ 4,11. Yang sah adalah verdict mekanisme/biaya, bukan klaim edge.

Disiplin komputasi

  • Dedup sebelum hitung. Telemetri loop mengandung ~12× baris duplikat; tanpa dedup false-positive melonjak dari ~5% ke ~58%.
  • Desimal, bukan float. anantara/arith_oracle.py memeriksa order sane dan klaim desimal.
  • Welch fail-closed. _welch_p() kini menolak scipy hilang, p non-finite, dan menangani sampel konstan secara deterministik.
  • Kontrol negatif wajib. PRAREG-41: blokir 3 simbol acak harus gagal; PRAREG-42: 200 sel acak harus ≥95% gagal; PRAREG-40: refleksi diacak harus gagal.
  • n<20 = MONITOR, bukan “signifikan” dan bukan “tidak ada edge”.

09Workflow Operasional

Empat workflow yang saling bertumpu: riset harian, eksekusi paper, keamanan, dan deploy.

1. Workflow riset harian

  1. Kolektor menulis data pasar & snapshot wallet.
  2. Signal engine menghasilkan kandidat; paper engine mengeksekusi di buku nyata dengan uang paper.
  3. Pukul 06:40 WIB settlement hanya untuk trade selesai & bar tertutup.
  4. 06:45 / 06:50 / 06:55 overlay PRAREG-40 / 41 / 42 ditulis.
  5. Readoutharian: n, mean, CI95, BH q, kontrol negatif; MONITOR bila n<20.
  6. Keputusan: KILL / FIX / LOLOS-kandidat. Tidak ada kandidat yang otomatis live.

2. Workflow eksekusi (jika nanti diizinkan)

  1. Preflight → 0 FAIL.
  2. Planner: tanpa short, tanpa leverage (Fase 1), jual ≤ saldo, beli ≤ USDC, min notional $5.
  3. Order limit-IOC, batas slip 30 bps, tanpa retry.
  4. Log append-only forward/live_exec.jsonl; intent tanpa result = rekonsiliasi manual.
  5. Watchdog membandingkan posisi venue dengan state lokal setiap siklus.

3. Workflow keamanan (wajib)

watchdog → data/sodex_watchdog_status.json
         → preflight check_reconciliation()
         → BLOCK bila: FAILED / stale / CRITICAL / endpoint incomplete / account mismatch

promotion gate → exit 3 DATA_KURANG → BLOCK (bukan INFO)
ledger hilang  → ok=False → BLOCK
exception      → status ERROR + alert WATCHDOG_ERROR + exit 2

4. Workflow deploy (ketika saatnya)

pytest tests/test_sodex*.py PASS
governor --selfcheck PASS
git diff review + secret scan + syntax check
systemctl --user restart anantara-daemon   ← HANYA dengan GO Owner
monitor log
Posisi hari ini: workflow deploy tidak dijalankan. Yang pernah direstart hanya monitoring read-only (anantara-sodex-watchdog.service), bukan daemon trading/live engine.

20Glosarium A–Z

Istilah yang dipakai di dokumen dan kode harian.

A–F

  • Alpha_net — return setelah fee, slippage, funding, dan beta BTC.
  • Arm — cabang eksperimen dengan konfigurasi berbeda.
  • BH-FDR — koreksi Benjamini–Hochberg untuk multiple testing.
  • Beta_side — +1 long, −1 short, untuk netralisasi BTC.
  • Bucket — unit waktu 5 jam; 144 bucket = 30 hari.
  • CI95 — interval kepercayaan 95%.
  • Deep loop — pembelajaran otonom berkesinambungan 24/7.
  • Dedup — hapus baris telemetri duplikat sebelum statistik.
  • Expectancy — expected value per round-trip setelah biaya.
  • Fail-closed — bila ragu, gate ditutup, bukan dibuka.
  • Fill — order tereksekusi; bukan sekadar accepted.
  • Forward — data setelah desain dibekukan.

G–N

  • Gate — syarat yang harus lulus sebelum tindakan lanjut.
  • Governor — pengawas expectancy & risiko; safety-critical.
  • Hit rate — persentase window yang mencapai target.
  • IOC — immediate-or-cancel; sisa tak terisi dibatalkan.
  • KILL — file penanda penghentian darurat.
  • Lane — satu alur paper eksperimen.
  • Live_armed — file tanda tangan Owner; sync dengan hash engine.
  • MDE — minimum detectable effect.
  • MDD — maximum drawdown dari puncak ekuitas.
  • North Star — ≥0,8% total wallet/window 30 jam.

O–S

  • N=1.271 — jumlah uji dalam registry dengan ambang Bonferroni.
  • OOS — out-of-sample.
  • OBI/OFI — order-book/order-flow imbalance.
  • Preflight — pemeriksaan sebelum live.
  • PRAREG — pra-registrasi eksperimen beku.
  • Promotion gate — gate kenaikan status target operasional.
  • PVE — perps volume engine.
  • Rekonsiliasi — cocokkan posisi venue dengan state lokal.
  • Residual — sisa posisi/ukuran setelah order parsial.
  • Shadow — simulasi tanpa eksekusi nyata.
  • Slippage — selisih harga expected vs filled.

T–Z

  • Settlement — finalisasi PnL setelah bar tertutup.
  • SHORT 00–05 — sel PRAREG-42, jam UTC.
  • Spot equity — nilai bersih akun spot; sentinel negatif bukan batas aman.
  • Stale — data/status terlalu lama.
  • Taker — order yang langsung cocok dengan book.
  • Telemetry OK — proses hidup; bukan profit.
  • UNSETTLED — data kurang untuk settlement; jangan dikarang.
  • UNTRACKED — posisi venue tanpa catatan state lokal.
  • Watchdog — monitor rekonsiliasi dan status sistem.
  • Welch — uji t untuk dua sampel varians berbeda.
  • Window — unit waktu penilaian target (30 jam).
