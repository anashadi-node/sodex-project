## §1 Model fill (DIBEKUKAN — primer = PENETRASI, konservatif)

Order dipasang pada **harga close bar-t** dan hanya aktif selama **bar t+1** (entri), atau sampai
kedaluwarsa (keluar).

| Arah | Terisi bila | Harga eksekusi |
|---|---|---|
| BUY limit `L` | `open(t+1) ≤ L` | `min(open, L)` — gap = harga lebih buruk |
| BUY limit `L` | `low(t+1) < L` (**tegas di bawah**, bukan sentuh) | `L` |
| SELL limit `U` | `open(t+1) ≥ U` | `max(open, U)` |
| SELL limit `U` | `high(t+1) > U` (**tegas di atas**) | `U` |

- Order yang tidak terisi **dibatalkan** (tidak mengejar harga).
- **Adverse selection** tertangkap oleh syarat fill itu sendiri: hanya terisi saat harga bergerak
  mendekati level kita.
- **Biaya**: maker **0,02%/sisi** (Binance USDM), **0,015%/sisi** (Hyperliquid).
- **Keluar paksa** (limit kedaluwarsa): taker **0,05%/sisi** (Binance) / **0,045%/sisi** (HL)
  **+ slippage 0,02%** (dibebankan sekali).
- **Varian sensitivitas** (dilaporkan, **TIDAK dipakai untuk putusan**): (i) *touch-fill*
  (`low ≤ L` / `high ≥ U`) = batas optimistis; (ii) *selalu terisi di close* = baseline R4 (taker).

**Keterbatasan yang diakui di muka**: tanpa data tick/1-menit pada periode DEV, model ini tidak
memodelkan posisi antrian (queue position) maupun kedalaman buku. Karena itu fill "penetrasi"
dipilih sebagai primer (lebih ketat daripada "sentuh"), dan **laju fill wajib dilaporkan**.

### §1b KOREKSI MODEL — dicatat 05-Okt **SEBELUM evaluasi** (setelah smoke test 2 bulan BTC)

Smoke test mekanika (BTC 01-Jan→01-Mar-2023, **bukan** data evaluasi) membuka dua cacat model.
Keduanya diperbaiki **sebelum** harness evaluasi dijalankan; parameter §1–§3 lain tidak berubah.

| # | Cacat | Akibat | Koreksi |
|---|---|---|---|
| **M-1** | Harga fill `min(open, L)` / `max(open, U)` | Itu semantik **market order (taker)** — pembeli dapat harga lebih baik dari limitnya, padahal order istirahat tidak bisa | Harga fill **selalu = limit** (`L`/`U`). Syarat terisi tetap: `open` melewati limit, atau `low < L` / `high > U` (penetrasi) |
| **M-2** | Limit keluar H11 diuji mulai bar horizon `gh` | Limit dipasang di `close(gh)` — harga itu baru diketahui **di akhir** bar `gh` → **look-ahead** | Limit aktif mulai bar `gh+1`, kedaluwarsa 6 bar, keluar paksa di `close(gh+6)` |
| **M-3** | Limit tepat di harga acuan (touch) | Order jadi *marketable* → bukan maker; laju fill 100% | **Margin antrian** `q = 5 bp` (proxy spread): entri `close x (1 ∓ q)`, keluar `close(gh) x (1 ± q)`. Primer = 5 bp. **Sensitivitas dilaporkan (bukan putusan)**: `q = 0` (optimistis) dan `q = 10 bp` (konservatif) |

Catatan jujur: dengan `q` positif, model memberi **perbaikan harga pasif** (beli di bawah acuan,
jual di atas acuan) — inilah keuntungan maker yang diuji. Karena itu **wajib** dilaporkan bersama
sensitivitas `q`, dan putusan memakai `q = 5 bp` (proxy spread koin mayor: Binance USDM 1–2 bp,
alt 5–10 bp). H12 **tidak** terpengaruh: limit-nya sudah 0,5 x ATR dari harga (≈ 0,5–1%), jauh
dari touch, sehingga risiko *marketable* kecil.

## §3 Hipotesis (DIBEKUKAN — tanpa grid search)

### H11 — "sinyal BEKU + entri pasif" (isolasi efek biaya)
- **Sinyal tidak diubah**: H11a = fungsi `h1()` dari `r4_dev_harness.py` **verbatim** (momentum:
  `close > SMA200h` dan `ret24 > 0` → long; cerminnya → short; hold 48 jam).
  H11b = fungsi `h4()` **verbatim** (mean-reversion: `z(r48) < −2` dan ATR% persentil ≥ 0,8 → long;
  cerminnya → short; hold 48 jam).
- **Entri**: limit pada `close(bar sinyal)`, kedaluwarsa **1 bar**. Tidak terisi → **tidak ada trade**.
- **Keluar**: pada horizon beku (48 jam setelah entri) pasang limit pada `close` bar itu,
  kedaluwarsa **6 bar**; bila gagal → **keluar paksa** (taker + slippage).
- Tujuan: mengukur apakah **hanya biaya** yang membunuh H1/H4, atau sinyalnya memang mati.

### H12 — "penyedia likuiditas pasif" (mean-reversion maker murni)
- `ATR%` = `ATR14(4 jam) / close(4 jam)`, di-*reindex* ke grid 1 jam (ffill) — rumus sama dengan
  `h4()`; **tidak ada parameter bebas**.
- **Entri (dua arah, satu posisi per simbol)**: limit long di `close x (1 − 0,5 x ATR%)`;
  limit short di `close x (1 + 0,5 x ATR%)`; kedaluwarsa **1 bar**; tidak terisi → tidak ada trade.
- **Keluar**: limit pada `entri x (1 ± 1,0 x ATR%)` (R:R 2:1), kedaluwarsa **24 bar**;
  bila gagal → keluar paksa (taker + slippage).
- Tanpa filter sinyal: murni menyediakan likuiditas 0,5 ATR dari harga.
