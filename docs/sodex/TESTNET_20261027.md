# Testnet SoDEX — catatan validasi 27-Okt-2026

## Fakta terukur
| Uji | Perintah | Hasil |
|---|---|---|
| Akun testnet | `account-id` | aid **57462** (mainnet 180570 — beda, wajib oracle) |
| Saldo spot testnet | `balance spot` | **1000 vUSDC** |
| Saldo perp testnet | `balance perps` | kosong |
| Order perp $5 | `orders place perps` | `notional is invalid` → **format & auth lolos**, gagal minimum $10 |
| Order perp $25 tanpa API key | sama | `API key error: API key not found` |
| Transfer type 3 → 999 | `transfer` | `API key error: API key not found` |

## Body transfer yang benar (ditangkap via proxy lokal, bukan tebakan)
```
POST /api/v1/spot/accounts/transfers
{"id":1793066432377,"fromAccountID":57462,"toAccountID":999,"coinID":1,"amount":"100","type":3}
Header: X-Api-Chain: 138565, X-Api-Nonce: <detik>, X-Api-Sign: 0x01<65 byte>
```
Dokumen resmi: Spot→Perps = **PERPS_WITHDRAW (type 3)**, tujuan **999**. Bukan `PERPS_DEPOSIT`.

## Blocker
Endpoint **transfer spot** menolak tanda tangan master wallet di testnet: `API key not found`,
meski header `X-API-Key` tidak dikirim (diverifikasi lewat capture). Order perp menerima
tanda tangan master; **transfer tidak**. Jadi transfer testnet butuh **API key testnet terdaftar**.

## Konsekuensi
Validasi fill nyata (orderID/partial/cancel) di perp testnet **belum bisa** sampai akun perp
testnet punya margin. Dua jalan: (a) UI transfer 100 USDC → Futures, (b) daftarkan API key testnet.

## Yang sudah tervalidasi tanpa dana
- Format order perp SoDEX diterima engine (error hanya soal notional/margin, bukan skema).
- Spesifikasi venue: step BTC 0,00001; minNotional $10; fee taker 4 bps.
- Eksekutor: `--lp` eksplisit (Q1 1,5), guard live 4 kunci, anti-fill-phantom, 15 tes lulus.

## Akar masalah sebenarnya (27-Okt, terverifikasi)
`.env` memuat **API key**, bukan kunci master:

| Variabel | Isi | Alamat |
|---|---|---|
| `SODEX_ADDRESS` | master wallet | `0x0794…ef47` |
| `SODEX_PRIVATE_KEY` | kunci API (bukan master) | `0x21BA…3f2D` |
| `SODEX_API_KEY` | nama API key (13 char) | — |

Konsekuensi:
1. CLI `bin/sodex` menandatangani dengan prefix **0x01** (mode API key). API key itu
   terdaftar di **mainnet**, tidak di testnet → `API key not found`.
2. Tanda tangan **master (0x02)** tidak mungkin dibuat: kunci master tidak ada di `.env`
   (sesuai prinsip #1 — kunci master tidak disimpan agen/bot).

`lev_20261026/sodex_master_sign.py` sudah dibuat sebagai jalur resmi 0x02
(payloadHash keccak256 compact JSON, EIP-712 ExchangeAction, domain spot/futures),
tetapi **tidak bisa dipakai** sampai kunci master tersedia — dan itu memang tidak
boleh dilakukan otomatis.

## Jalan keluar
Transfer testnet harus ditandatangani pemilik master wallet:
- UI testnet (wallet terhubung), atau
- faucet di dalam tab **Futures/Perps** bila tersedia (klaim 100 USDC harian).

## Investigasi UI (28-Okt) — kenapa "Enable Trading" & transfer gagal
Dokumen resmi *Testnet Onboarding Steps*: (4) tambahkan ValueChain ke wallet,
(5) transfer EVM→Spot, (6) setujui di wallet, (7) **Enable Gas-Free Trading**,
(8) order pertama. "Enable Trading" = tanda tangan pesan gas-less di wallet.

Bukti terukur untuk alamat `0x0794…ef47` di testnet:
| Pemeriksaan | Hasil |
|---|---|
| `eth_chainId` testnet RPC | `0x21d45` = 138565 ✓ |
| Saldo native SOSO | **0** |
| Riwayat transaksi testnet EVM | **0 transaksi** (alamat belum pernah menandatangani) |
| Spot testnet | 1100 vUSDC (aid 57462) |
| Perps testnet | akun ada, `av=0` (belum enabled/funded) |

Kesimpulan: backend SoDEX baik; yang belum terjadi adalah **tanda tangan wallet pada
chain testnet 138565**. Tanpa itu "Enable Trading" tidak pernah selesai, dan transfer
Spot→Perps ikut gagal (keduanya butuh signature).

Parameter jaringan testnet (dokumen resmi):
```
Network Name : ValueChain Testnet
RPC URL      : https://testnet.valuechain.xyz
Chain ID     : 138565
Symbol       : SOSO
Explorer     : https://test-scan.valuechain.xyz
```
Catatan: halaman FAQ hanya memuat parameter **mainnet** (286623). Bila "Switch to
ValueChain" menambahkan mainnet, wallet berada di chain yang salah saat app testnet
meminta tanda tangan domain `chainId 138565` → wallet menolak / popup tidak muncul.

## Anatomi tombol "Enable Trading" (dari bundle app testnet)
`enableTrading()` → `Qy({mode:"embedded"})` → `Sge()` → `al(wallet,"sign_in")`:
1. minta **tanda tangan sign-in** ke wallet,
2. simpan **session terenkripsi** (`Sde(...)`),
3. wajib `kind === "wallet-session"`, jika tidak → `ACCOUNT_NOT_READY`
   (pesan UI: "Wallet address or user ID is incomplete").

Jadi "Enable Trading" **bukan** transaksi on-chain; ia sesi web. Kalau popup tidak
muncul / tanda tangan gagal / session gagal disimpan, tombol kembali ke keadaan semula
dan transfer Spot→Perps ikut tertahan (transfer juga butuh tanda tangan).

Bukti pendukung: alamat `0x0794…` **0 transaksi** di chain 138565, saldo SOSO 0,
base fee 0,001 gwei (jadi bukan soal biaya).

Mode kegagalan & perbaikan:
| Gejala | Sebab | Tindakan |
|---|---|---|
| Klik, tak ada popup | konflik ekstensi / WalletConnect | pakai ekstensi MetaMask langsung, matikan wallet lain, refresh |
| Popup muncul, sign, balik ke tombol | session gagal disimpan | clear site data (localStorage + IndexedDB), reconnect |
| Toast "insufficient funds"/tx gagal | SOSO 0 | isi SOSO testnet |
| Wallet Safe/AA (smart contract) | sign-in EOA-only | pakai EOA |

## Jalur bypass (paling cepat)
Buat **API key testnet** di app (Settings → API Keys). Bila signature di halaman itu
berhasil, transfer Spot→Perps dan seluruh order dapat dijalankan server-side
(prefix 0x01 + header `X-API-Chain: 138565`) tanpa bergantung pada alur session.

## Vonis testnet (28-Okt): buntu by design, bukan kesalahan pengguna
Bukti UI: `testnet.sodex.com/apikeys` → **"Not available on Testnet"** (screenshot).
Bukti kode: `Enable Trading` membuat **wallet-session** yang di dalamnya berisi
`session.apiKey` (`fs()` memeriksa `session.apiKey.expiresAt`), dan SDK membuatnya lewat
`POST /accounts/api-keys` (`addApiKey`, ditandatangani master). Fitur itu dimatikan di
testnet → tombol tidak akan pernah selesai, berapa kali pun diklik.

Rantai blokir lengkap:
1. Transfer Spot→Perps butuh tanda tangan **master (0x02)** atau **API key terdaftar**.
2. Kunci master tidak ada di `.env` (benar, prinsip #1) → tidak bisa ditandatangani agen.
3. API key mainnet (`0x21BA…`) **tidak terdaftar di testnet** — diuji 3×: `API key not found`.
4. API key testnet tidak bisa dibuat: halaman dimatikan di testnet.
5. `Enable Trading` (satu-satunya penanda tangan yang tersisa) = pembuatan API key
   wallet-session → ikut dimatikan.

Kesimpulan: **perps testnet tidak dapat dipakai untuk validasi fill** saat ini.
Formal: `BLOCKED_BY_PLATFORM`.

Konsekuensi untuk 01-Des: jalur fill nyata hanya bisa divalidasi lewat order mainnet
berukuran minimum (min notional $10), atau menunggu SoDEX mengaktifkan API key/faucet
perps di testnet.
